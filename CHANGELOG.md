# Changelog

All notable changes to `OWNd` are documented in this file.

## [Unreleased]

### Fixed
- **WHO 25 (`OWNDryContactCommand.status_for_sensor`, `OWNDryContactEvent`)**: the event parser strips the leading `3` of a dry-contact WHERE (`*25*31#1*339##` -> `sensor` `39`), which is what the emulated gateways do (`*#25*35##` polls sensor `05`, `*#25*39##` sensor `09`, `*#25*339##` sensor `39`, the prefix-less `*#25*5##` is refused 12/12; report 21 T1, ORACLE_CONFIRM.md), but `status('39')` built `*#25*39##`, i.e. sensor 09. `status(where)` keeps sending the bus-form WHERE verbatim (what `OWNDryContactEvent.where` carried and what MyHOME configures: `33`, `339` in the captures); the new `status_for_sensor(sensor)` is the inverse of `OWNDryContactEvent.sensor` and puts the prefix back (`status_for_sensor(39)` -> `*#25*339##`). The page grammar (`dry-contact-ir.md` #where: `1..201`, `[1-9][1-9]`, no prefix) and the firmware behaviour are both in the docstrings. A frame without the `#0` / `#1` parameter (`*25*31*33##`, not a published form) no longer reads as a detection: `is_detection` is `False`, the new `is_state_reply` tells `#0` from `#1`, and the log says the parameter is missing (report 21 T4).
- **WHO 25 (`OWNCENPlusEvent`)**: a pushbutton outside `0..31` or missing (`*25*21#40*21##`, `*25*21*21##`) gives `push_button` `None` instead of `0`, which is a real button (`cen-plus.md` #pushbutton-parameter; report 21 T2); a bare WHERE `2` carries no Object and gives `object` `None` (`cen-plus.md` #where---virtual-object; report 21 T4). Both are logged.
- **WHO 8 (`OWNIntercomCommand.end_call`)**: emits `*8*3#KIND#MMTYPE*4LOCAL##` with the literal `4` the touchscreen writer concatenates before the local address (`who-8` README #historical-touchscreen-call-model, TS10 call tests; report 21 I1): `end_call("11")` -> `*8*3#6#2*411##`. `where` is now required; the old default `END_ALL_CALLS` produced `*8*3#6#2*4##`, a misreading of the prefix as an "end all calls" broadcast that is on no page (all three spellings are `nack, silent` on the 12 emulated gateways). `END_ALL_CALLS` stays importable as a deprecated alias of the new `END_CALL_PREFIX` (`"4"`).
- **WHO 8 (`OWNIntercomEvent`)**: WHAT 6 `*8*6#LOCAL*ORIGINAL_CALLER##` exposes the WHERE as `original_caller` (`camera` is `None` on a cycling frame: the page says cycling targets the original caller, not a camera); WHAT 40 `*8*40#KIND#MMTYPE*CALLER##` fills `call_kind` / `multimedia_type`; WHAT 77 `*8*77#ID*LOCAL##` exposes `teleloop_id` (`teleloop_mode` stays as a deprecated alias) (`who-8` README #historical-touchscreen-call-model, #teleloop-and-local-multimedia-events; report 21 I2).
- **WHO 6 (`OWNDoorEntryCommand`)**: `open_lock`, `staircase_light_on` and `staircase_light_off` require an explicit WHERE (`ValueError` on an empty one) instead of defaulting to `0`: `*6*10*0##` is `nack, silent` on all 12 emulated gateways while `*6*10*4001##` goes out on four (ORACLE_CONFIRM.md row E1-door; the page's `4000..4095` is product-scoped and not enforced). `camera_on("")` raises instead of building the invalid `*6*0*##`. New `camera_cycle(where)` builder (`*6*18*WHERE##`) and `OWNDoorEntryEvent.is_camera_cycle` (`who-6` README #l4686sdk-reference; report 21 E1).
- **WHO 5 (`OWNAlarmEvent`)**: `zone` is an `int` for the `#Z` selector as it already was for the `ZS` sensor form (`*5*15*#2##` and `*5*15*21##` both give `2`; `"c"` / `"f"` for `#12` / `#15` unchanged; report 21 A2); `#9` is logged as "Auxiliary 9 (anti-panic)" with `is_auxiliary` `True` (`addressing.md`: `#0..#8` central zones, `#9` auxiliary, TS10 anti-panic filter `#9`; report 21 A3); `is_active` is WHAT 1 only (WHAT 11 is a zone state, `is_zone_active`), `is_disarmed` is WHAT 2 / 9 only and WHAT 0 maintenance has its own `is_maintenance` (`what.md`; report 21 A4).
- **Golden corpus (`who05_alarm.yaml`)**: `*5*2*0##` is relabelled from "Silent alarm event for zone 0" to WHAT 2 Disactivation on the central unit (id `alarm.event.disactivation.central`), `*5*1*0##` from "Arm system total/away" to WHAT 1 Activation (a state, not an arm), and `*#5*2##` is marked as the openwebnet4j spelling of the published `*#5*#2##` zone request (`what.md`, `protocol.md` #zone-status-request; report 21 A5). Frames and fields are unchanged; `corpus.json` regenerated with `tools/golden/validate_corpus.py`.

### Changed
- `OWNTransport.send()` takes the same `raise_on_error` keyword as `OWNCommandSession.send()` on `AsyncTcpTransport` and `AsyncSerialTransport`, and `OWNTransport.last_error` holds the error recorded by the last `send()`: a local refusal on both transports, and on the TCP transport everything its command session records (NACK, timeout, connection errors). Both transports now share one contract: `RuntimeError` when not connected, then a frame refused locally is logged at ERROR, kept in `last_error` and answered with `None`, or raised as `OWNProtocolError` with `raise_on_error=True`.
### Fixed
- **WHO 4 Dimension 22 is sent only in its published split form**: Dimension 22 is the published split-unit IR control (`*#4*3#Z#N*22##` / `*#4*3#Z#N*#22*MOD*SP*VEL*SWING##`, WHO 4 specification pp. 66-68). Sent to a zone (`*#4*Z*22##`, `*#4*0ZZ*22##`), to every zone (`*#4*0*22##`) or to the central unit (`*#4*#0*22##`), as a read or a write, it crashes the thermoregulation daemon (`bt_termo`) on nine of the twelve emulated Linux IP gateways and reboots an F461 2.0.11 about three minutes later (own-firmware-oracle `thermo-dim22` suite and `tools/expected_divergences.yaml` crash frames, live F461 2.0.11). The published split forms `3#Z#N` crashed none of the twelve emulated gateways and ten forward them to the bus as a telegram to zone Z, actuator N (own-firmware-oracle `findings/thermo-dim22.md`; emulated firmware, not yet replayed on hardware), so their canonical spelling is sent: `Z` 1..99, `N` 1..9, a request (`*22`) or a write with exactly the four payload fields (`MOD` 0..5, `SP` three or four digits, `VEL` 0..4, `SWING` 0 or 1, each optionally empty as the touchscreen writes them). Everything else stays refused: the prefix-less `*#4*Z#N*22##` (`nack, silent` on eleven gateways, forwarded by the MH202 only), `Z` 0, leading zeros, whitespace, `+` or newline tokens, non-ASCII digits, `#Z`, `#0#C`, `Z#4#IF`, `N` 0 or two digits, a parameter after the request, a write with fewer or more than four fields or out-of-range values. `OWNCommandSession.send` (and so `AsyncTcpTransport.send` and `keepalive`), and `AsyncSerialTransport.send` refuse a crash form before anything is written, with the contract above and `reason="destructive_frame"`; `OWNCommandSession.send_to_gateway` refuses it before `connect()` (no socket, no handshake), logs it at ERROR and answers `None`, or raises `OWNProtocolError` with `raise_on_error=True` (the session it would have used is discarded, so no `last_error` is observable on that path). The detector `is_who4_dimension_22()` recognises every Dimension 22 spelling; the send paths refuse `is_who4_dimension_22_crash_form()`, both public, accepting `bytes`, and anchored to the first `*` of each frame, so a mid-frame WHERE `#4` / DIMENSION `#4` such as `*#2*#4*#11#001*22##` or `*#1*14*#4*1*22##` stays sendable. Parsing is unchanged: the frame can still be read from the bus.
- **`AsyncSerialTransport.send` validates outbound frames** like `OWNCommandSession.send`: an invalid or signaling frame (for example the single-`#` concatenation `*1*1*11#*#4*2*22##`) is refused with `reason="invalid_frame"` instead of being written to the port. The frame is serialised once, terminator included: the string checked is the string written.
- **WHO 4 central-unit builders (`OWNHeatingCommand.set_central_mode`, `set_central_temperature`, `set_central_program`, `set_central_scenario`, `set_central_weekend`, `set_central_holiday`, `set_holiday_end_date`, `set_holiday_end_time`, `set_timed_manual_end_time`)**: one shared `_validate_central_where` guard raises `ValueError` unless `where` is the central unit itself: `#0` (3550, 99 zones) or `#0#C` with `C` the 4695 unit's configured zone 1..99 or `01`..`99` (the forms MyHOME and the golden corpus use; whitespace is stripped, the stripped value is quoted). The plain zone form `*4*311*Z##` is `nack`/`silent` on all 12 emulated gateways (own-firmware-oracle `thermo-zone-mode`, `ownd-pr82-heating`) and on a live F461 2.0.11.
- **WHO 4 (`OWNHeatingEvent`)**: a Dimension 14 setpoint reply with a `#`-prefixed value (`*#4*#1*14*#0230*1##`, `MyHOME#139`) parses as a 23.0 °C target temperature instead of `None`; `dimension_value` keeps `#0230`.

  - Firmware oracle conformance suite across emulated gateways (`#84`, `#117`, `#126`).
  - Unified documentation synchronization sentinel (`scripts/sync_documentation.py`) verifying WHO catalog, gateway profile tables, and coverage badges (`#101`, `#105`, `#108`).

### Changed
- **Packaging & Dependencies**:
  - Normalize version string to canonical PEP 440 (`2.0.0b11`).
  - Migrate package metadata to PEP 621 `[project]` and PEP 639 `license = "Apache-2.0"` in `pyproject.toml`.
  - Drop unused `pytz` and `python-dateutil` runtime dependencies in favor of Python 3.11+ standard library `datetime` and `zoneinfo` (with `tzdata` included in `[test]` on Windows).
- **Input Validation & Connection Reliability**:
  - Harden bounds and infeasible input validation across WHO subsystems and connection sessions (`#121`, `#125`, `#127`, `#128`).
  - Only retry idempotent status queries in `OWNCommandSession` after mid-send transport loss (`#131`).
  - `OWNCommandSession.send()` reconnects at most once, with a 2 s cooldown, instead of running the full backoff while holding the send lock; routine send logs move from `INFO` to `DEBUG` (`#132`). Callers that need the full 5-attempt retry, such as after closing an idle socket on a single-slot MH201, call `connect()` first (`#133`).
- **API**:
  - `set_datetime_to_now`, `set_date_to_today` and `set_time_to_now` accept a `datetime.tzinfo` as well as an IANA name; transport `send` accepts `str | OWNMessage`; `OWNd.connection` uses static re-exports (`#132`).
  - `OWNd.connection.gateway` no longer resolves `find_gateways` / `get_gateway` / `get_port` through the package at call time, so tests must patch `OWNd.connection.gateway.*` (`#133`).
  - WHO 13 builders raise `ValueError` for UTC offsets that are not whole hours (for example `Asia/Kolkata`), which the `0HH` / `1HH` field cannot carry, instead of truncating them (`#129`).
